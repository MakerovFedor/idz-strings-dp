# ИДЗ №2: Поиск подстрок и расстояние Левенштейна

**Дисциплина:** Информатика и алгоритмизация, МФТИ, 1-й семестр.  
**Индивидуальный вариант:** поиск подстроки с помощью Z-функции; расстояние Левенштейна.

## О проекте

Проект посвящён исследованию алгоритмов поиска подстроки и сравнения последовательностей. Рассматриваются зависимость времени работы от размера и структуры входных данных, количество элементарных операций и дополнительная память алгоритмов.

Реализованы:

- наивный поиск всех вхождений подстроки и поиск на основе Z-функции; для сравнения используется стандартный метод Python `str.find()`;
- расстояние Левенштейна тремя способами: наивная рекурсия без кэширования, динамическое программирование с полной таблицей и восстановлением правок, динамическое программирование с двумя строками;
- автоматизированные проверки корректности, генераторы тестовых данных, сбор результатов измерений и построение графиков.

Алгоритмическое ядро написано на Python без сторонних библиотек. Экспериментальная часть использует стандартные модули `time`, `tracemalloc`, `csv`, `random`, а построение графиков — Matplotlib и SciPy.

## Проверка корректности

Запуск автоматических тестов:

```cmd
python -m unittest discover -s tests -v
```

Пример работы алгоритмов поиска:

```python
from search import naive_search, z_search

print(naive_search("ababa", "aba"))  # ([0, 2], 7)
print(z_search("ababa", "aba"))      # позиции [0, 2] и счётчик сравнений
```

В обоих случаях находятся все вхождения, включая перекрывающиеся. Пустой паттерн считается встречающимся на каждой границе текста: от `0` до `len(text)` включительно.

Пример вычисления расстояния Левенштейна:

```python
from levenshtein import levenshtein_table

distance, edit_script, operations = levenshtein_table("кот", "кит")
```

Значение `distance` в этом примере равно `1`. `edit_script` содержит последовательность операций в формате JSON, а `operations` — число вычисленных внутренних ячеек таблицы. Для независимой проверки восстановления правок предусмотрены функции `apply_edit_script()` и `count_edit_cost()`.

## Экспериментальная методика

Для поиска подстроки используются пять типов данных: случайная латиница, случайная ДНК, вырожденный случай с повторяющимися символами, перекрывающиеся вхождения и ложные префиксы. Исследуется зависимость от длины текста `N` при фиксированной длине паттерна `M` и от `M` при фиксированном `N`.

Для расстояния Левенштейна рассматриваются независимые ДНК-последовательности и мутировавшие копии. Наивная рекурсия измеряется только на коротких строках; для табличных реализаций предусмотрена более широкая сетка размеров.

Время выполнения измеряется с помощью `time.perf_counter()` без учёта генерации входных последовательностей. Пиковая дополнительная память для вариантов Левенштейна измеряется отдельно с помощью `tracemalloc`. Для каждой точки предусмотрены повторные запуски на различных фиксируемых случайных зернах. Результаты сохраняются в CSV с указанием параметров входа и отдельных измерений.

### Пробный запуск с уменьшенной сеткой

```cmd
python benchmarks.py --suite search-n --scale quick --repeats 2
python benchmarks.py --suite search-m --scale quick --repeats 2
python benchmarks.py --suite dp-recursive --scale quick --repeats 2
python benchmarks.py --suite dp-tables --scale quick --repeats 2
python plots.py --scale quick
```

### Полная сетка измерений

```cmd
python benchmarks.py --suite search-n --scale full --repeats 5
python benchmarks.py --suite search-m --scale full --repeats 5
python benchmarks.py --suite dp-recursive --scale full --repeats 5
python benchmarks.py --suite dp-tables --scale full --repeats 5
python plots.py --scale full
```

Полные серии поиска включают тексты длиной до 500 000 символов; табличные варианты Левенштейна — строки длиной до 3 000. Для медленных случаев наивных алгоритмов в коде установлены ограничения на размеры. Измерения полной таблицы могут требовать значительного времени и объёма оперативной памяти.

Результаты записываются в `results/` под именами `search-n_full.csv`, `search-m_full.csv`, `dp-recursive_full.csv`, `dp-tables_full.csv`. Графики сохраняются в `figures/`. При прерывании серии промежуточные записи остаются в файле с суффиксом `.partial`; файл с окончательным именем создаётся после завершения серии.

## Графики и отчёт

Скрипт `plots.py` строит четыре серии графиков по сохранённым CSV:

1. время поиска в зависимости от длины текста `N` в линейном и логарифмическом масштабах;
2. время поиска и количество сравнений в зависимости от длины паттерна `M`;
3. время работы рекурсивного и табличных решений Левенштейна с аппроксимацией зависимости от длины строк;
4. пиковая дополнительная память табличного ДП и варианта с двумя строками.

При обработке повторных измерений вычисляются среднее значение и выборочное стандартное отклонение. Метод `str.find()` служит эталоном скорости, однако число внутренних сравнений символов в нём не измеряется.

`report.ipynb` содержит описание алгоритмов, тестов, методики экспериментов и интерпретации результатов. Для отображения экспериментальных таблиц и графиков используются файлы из `results/` и `figures/`. Количественные выводы требуют фактически выполненной полной серии измерений.

## Особенности реализаций

- `comparisons` — число посимвольных сравнений у собственных поисковых алгоритмов; при расчёте Z-функции исключены сравнения с искусственным разделителем.
- `ops_count` — число рекурсивных вызовов для наивного Левенштейна либо число вычисленных внутренних ячеек для табличных версий.
- Полная таблица Левенштейна имеет временную и пространственную сложность `O(N·M)` и поддерживает восстановление правок.
- Вариант с двумя строками сохраняет временную сложность `O(N·M)`, но уменьшает дополнительную память до `O(min(N, M))`; полная последовательность правок в этой реализации не восстанавливается.
- Наивная рекурсия не использует запоминание результатов и имеет экспоненциальную оценку времени в худшем случае.

## Ограничения

Экспериментальные характеристики зависят от конфигурации компьютера, версии интерпретатора Python и условий выполнения измерений. Сравнение с `str.find()` отражает различия между собственными Python-реализациями и встроенным методом. Данные для основного исследования генерируются синтетически; анализ реальных FASTA-последовательностей не входит в текущую реализацию.
